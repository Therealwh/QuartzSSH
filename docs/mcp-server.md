# MCP-сервер QuartzSSH («мост для AI-агентов»)

Опциональный встроенный MCP-сервер (раздел 26 ТЗ): AI-агент (opencode, Claude
Code, Cursor и любые MCP-клиенты) может выполнять команды и работать с файлами
на подключениях, уже открытых в QuartzSSH.

**Ключевой принцип: выключено по умолчанию.** Пока вы явно не нажали
«Запустить» в настройках, приложение не слушает ни один порт — сетевых
поверхностей нет вообще.

## Включение

1. Настройки → **MCP-сервер для AI-агентов**.
2. При первом включении появится предупреждение — подтвердите его.
3. Нажмите **«Запустить»**. Приложение:
   - биндит TCP строго на `127.0.0.1:<порт>` (никогда не `0.0.0.0`);
   - генерирует Bearer-токен (32 случайных байта, base64url, 43 символа);
     токен живёт только в памяти до «Остановить»/перезапуска;
   - показывает токен один раз — скопируйте его кнопкой «Копировать».
4. Отметьте **разрешённые подключения** (allowlist) — чекбоксы профилей.
   Пустой список = агенту не доступно ничего.
5. При необходимости задайте порт (допустимый диапазон **47200–47300**,
   по умолчанию 47215) и режим подтверждений.

«Перегенерировать» перезапускает сервер с новым токеном (прежний инстанс
останавливается). «Остановить» полностью закрывает порт. При запуске
приложения сервер **не** стартует автоматически — только по кнопке.

## Headless mode (работа в фоне, 26.6)

MCP-сервер живёт в процессе QuartzSSH, поэтому по умолчанию закрытие окна
завершает и приложение, и сервер вместе с активными SSH-сессиями. Для
«безголовой» работы (агент работает, окно не нужно) есть настройка
**«Продолжать работу в фоне при закрытии окна»** (Настройки → Фоновый режим,
поле `closeToTray` в settings.json, по умолчанию выключена).

Сценарий:

1. Включите **Фоновый режим** тумблером в настройках (достаточно один раз).
2. Запустите MCP-сервер и откройте нужные SSH-сессии (сами сессии и файловые
   панели — как обычно, из интерфейса).
3. Закройте окно — приложение свернётся в трей, но не завершится: сервер,
   сессии и передачи продолжают работать, агент продолжает вызывать
   инструменты.
4. Вернуть окно — клик левой кнопкой по иконке в трее (или «Открыть
   QuartzSSH» в меню трея). Завершить приложение совсем — «Выход» в меню трея.

Иконка в трее присутствует всегда: и в обычном режиме (быстрый доступ),
и в фоновом. Подсказка иконки — «QuartzSSH»; клик ЛКМ показывает окно,
ПКМ открывает меню. Подтверждения MCP-инструментов показываются в окне
настроек, поэтому в headless-режиме безопаснее режим `destructive`: пока
окно скрыто, запрос подтверждения завершится отказом по таймауту.

## Модель безопасности

| Механизм | Реализация |
|---|---|
| Привязка к интерфейсу | `TcpListener::bind(("127.0.0.1", port))`, другого варианта в коде нет |
| Аутентификация | `Authorization: Bearer <токен>`; сравнение в constant-time; без/с неверным токеном — `401` |
| DNS rebinding | Заголовок `Host` обязан быть `localhost`, `127.0.0.1` или `[::1]` (порт допускается); иначе `403` |
| Allowlist | Инструменты видят только профили из `mcp.allowlistProfileIds`; сопоставление по id или точному имени |
| Без автовызовов извне | Мост **не подключается сам**: `ssh_exec`/`sftp_*` работают только с сессиями, которые пользователь уже открыл в приложении (учётные данные никогда не используются агентом напрямую) |
| Подтверждения | Событие `mcp:confirm {callId, tool, host, summary}` + oneshot (паттерн HostKeyGate); нет ответа за 120 с = отказ |
| Секреты | `list_hosts` возвращает только `id`, `name`, `host`; пароли/ключи агенты не видят никогда |

Режимы подтверждений (`mcp.confirmationMode`):

- `always` — подтверждать каждый вызов инструмента;
- `destructive` (по умолчанию) — подтверждать опасные команды
  (`rm -rf`, `mkfs*`, `shutdown`, `reboot`, `poweroff`, `halt`, `dd` — с учётом
  позиции в конвейере, чтобы `echo shutdown` не срабатывал) и перезапись
  существующих файлов через `sftp_write`;
- `never` — не спрашивать никогда (не рекомендуется).

Ограничение: диалог подтверждения показывается в настройках; если в момент
запроса вкладка «Настройки» закрыта, вызов завершается отказом по таймауту
(безопасное поведение по умолчанию).

## Инструменты

| Инструмент | Аргументы | Что делает | Ограничения |
|---|---|---|---|
| `list_hosts` | — | Профили из allowlist: `id`, `name`, `host` | Без секретов; пустой allowlist — ошибка `allowlist_empty` |
| `ssh_exec` | `host`, `command` | Выполняет команду в **уже открытом** SSH-сеансе; возвращает JSON `{"exitCode": N, "output": "..."}` | Таймаут 30 с; опасные команды — подтверждение; нет сессии — ошибка |
| `sftp_list` | `host`, `path` | Листинг каталога по SFTP | Нужен открытый SFTP-сеанс (вкладка «Файлы»); максимум 500 записей |
| `sftp_read` | `host`, `path` | Читает удалённый текстовый файл | Лимит 10 МиБ; бинарные файлы (NUL в начале) отклоняются |
| `sftp_write` | `host`, `path`, `content` | Создаёт или перезаписывает файл (CREATE+TRUNCATE) | Перезапись существующего требует подтверждения; `force` не поддерживается; бинарная запись не предусмотрена |

Транспорт: минимальный Streamable HTTP — `POST /mcp` с JSON-RPC 2.0
(`initialize` → capabilities+serverInfo, `tools/list`, `tools/call` →
`result.content[0].text`), уведомления отвечают `202`, всё остальное
(GET, другие пути) — `405`. Без SSE и keep-alive (`Connection: close`).

## Конфигурации клиентов

Токен храните в переменной окружения (ниже — `{env:QUARTZSSH_MCP_TOKEN}`),
не вписывайте его в файлы конфигурации.

### OpenCode (`opencode.json`)

```json
{
  "$schema": "https://opencode.ai/config.json",
  "mcp": {
    "quartzssh": {
      "type": "remote",
      "url": "http://127.0.0.1:47215/mcp",
      "enabled": true,
      "headers": {
        "Authorization": "Bearer {env:QUARTZSSH_MCP_TOKEN}"
      }
    }
  }
}
```

Эту же конфигурацию можно скопировать из приложения: настройка
«Показать конфигурацию для AI-клиента» подставляет текущий порт.

### Claude Code (`.mcp.json` или `claude mcp add`)

```json
{
  "mcpServers": {
    "quartzssh": {
      "type": "http",
      "url": "http://127.0.0.1:47215/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}
```

Или командой: `claude mcp add --transport http quartzssh http://127.0.0.1:47215/mcp --header "Authorization: Bearer YOUR_TOKEN"`.

### Cursor (`~/.cursor/mcp.json`)

```json
{
  "mcpServers": {
    "quartzssh": {
      "url": "http://127.0.0.1:47215/mcp",
      "headers": {
        "Authorization": "Bearer YOUR_TOKEN"
      }
    }
  }
}
```

## Аудит

Каждый вызов `tools/call` попадает в кольцевой буфер на 100 записей:
`{timestamp, tool, host, argsSummary, status}`. Значения аргументов длиннее
8 символов маскируются (`…`), поэтому содержимое файлов и длинные команды в
журнал не попадают. Просмотр — последние записи в разделе MCP настроек,
кнопка «Очистить» (команды `mcp_audit_list` / `mcp_audit_clear`).

## Модель угроз

- **Удалённый атакующий из интернета/LAN**: не может даже подключиться —
  порт слушает только loopback.
- **Другой процесс на этом компьютере без токена**: получает `401`; токен
  недоступен другим процессам (только память приложения и пользователь,
  скопировавший его).
- **Зловредный сайт в браузере (DNS rebinding)**: запрос будет отклонён по
  заголовку `Host` (`403`), даже если браузер резолвит чужой домен в
  127.0.0.1.
- **Украденный токен**: даёт доступ только к allowlist-профилям и только к
  открытым в приложении сессиям; опасные операции требуют клика пользователя.
  Компрометация лечится «Перегенерировать» или «Остановить».
- **Ошибки самого агента**: аудит с маскированием значений позволяет
  разобраться, что было сделано.

Остаточные риски: агент с токеном в режиме `never` может выполнить любую
команду на разрешённом хосте без подтверждений; не запускайте мост на
постоянной основе, если он не нужен.
