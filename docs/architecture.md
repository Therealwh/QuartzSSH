# Architecture

QuartzSSH is a desktop SSH/SFTP client built with Tauri 2: a Rust backend
for all network and storage operations, and a React + TypeScript frontend for
the interface. The two sides communicate over Tauri IPC (typed commands plus
event streams).

## Data flow: terminal session

1. `ssh_connect(profileId)` → `ssh::connect`:
   - loads the profile, resolves the password/passphrase from the OS
     credential store (or asks the frontend via `password_required`);
   - connects with russh; the host key is verified in
     `client::Handler::check_server_key` against `known_hosts`. New keys raise
     an `ssh:host-key` event and wait for the user's decision (Strict mode);
     changed keys are rejected unless explicitly accepted with a warning;
   - authenticates, opens a PTY channel, spawns a reader task that owns it.
2. Output flows back as `ssh:data` events (base64 payload), input goes
   through `ssh_write` → channel writer task; resizes via `ssh_resize`.
3. Disconnect produces `ssh:closed`; the frontend marks the tab and, if
   auto-reconnect is enabled for the profile, reconnects after a delay.

## Data flow: SFTP transfers

`sftp_open` reuses the live SSH session to open an SFTP subsystem channel.
Uploads/downloads run in spawned tasks that stream fixed-size chunks,
emit `sftp:transfer` progress events, and support cancellation through a
oneshot channel (`transfer_cancel`).

## Storage

| Data | Location | Notes |
| ---- | -------- | ----- |
| Profiles (`profiles.json`) | OS app-data dir | no secrets inside |
| Settings (`settings.json`) | OS app-data dir | security + update prefs |
| `known_hosts` | OS app-data dir | OpenSSH format |
| Passwords / passphrases | OS credential store (keyring) | per-profile entries |

## Key decisions

- **russh 0.65 with the `ring` crypto backend** — pure-Rust SSH stack with
  post-quantum KEX (`mlkem768x25519-sha256`) preferred by default.
- **xterm.js is code-split** and loaded only when a terminal is opened, keeping
  startup fast.
- **The updater key pair** is generated once; the public key is compiled into
  the app, the private key exists only as a protected CI secret. `latest.json`
  is generated by CI from signed artifacts and the release fails if any
  platform lacks a signature.

Planned modules (server monitoring, remote code editor, optional MCP server)
extend the same command/event layer without changing the core structure.
